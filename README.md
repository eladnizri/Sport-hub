# חמ״ל ספורט

> **⏸️ הפרויקט מושהה.** ההרצה המתוזמנת שמושכת נתונים כבויה
> (`.github/workflows/refresh-data.yml`) — היא רצה 12 פעמים ביום ונכשלה
> בכל פעם כי הסודות לא הוגדרו. הקוד עצמו תקין ועובר build; האתר, אם
> ייפרס, ירוץ על נתוני דמו. להמשך מתישהו: ראה "הקמה" למטה, ואז בטל את
> ההערה משורות ה-cron בקובץ ה-workflow.
>
> נקודת פתיחה אם חוזרים לזה: הדבר הראשון לבדוק הוא
> **Settings → Pages → Source** — צריך להיות "GitHub Actions".

אפליקציית סקירה אישית — לא אפליקציית תוצאות, ולא מעקב חי. פותחים אותה
כדי לדעת מה קורה: מה קרה בחדשות, איפה כל קבוצה במעגל שלך עומדת, ומה
הטבלאות אומרות. ממשק בעברית, RTL מלא, מותאם קודם כל לנייד.

העיקרון: **הקשר במקום ניטור**. משחק הוא עובדה בשורה אחת — תוצאה אם
הסתיים, שעה אם עוד לא. אין שעון שמתקתק, אין "חי", אין מסך שנועד
להישאר פתוח תוך כדי משחק.

## מה יש בפנים

| מסך | השאלה שהוא עונה עליה |
| --- | --- |
| **סקירה** | מה קרה — פיד חדשות: תוצאות, תנועת טבלה, העברות, וכותרות אמיתיות אם קיימות |
| **קבוצות** | מה המצב אצל כל קבוצה במעגל שלך — מיקום בטבלה, תוצאה אחרונה, המשחק הבא |
| **טבלאות** | איפה כל קבוצה בטבלה, כולל מה משחקי היום עושים לה |

### שלושת הרעיונות שמניעים את זה

**מעגל מעקב, לא "כל הליגה".** קבוצות ישראליות ומועדוני לגיונרים נכנסים
אוטומטית; אתה מרחיב או מצמצם ממסך קבוצות. `src/lib/circle.ts` קובע מי
בפנים, ואותו מעגל מסנן גם את פיד הסקירה — לא כל תוצאה בכל ליגה, רק מה
שאכפת לך ממנו.

**"היום" בטבלה, לא "עכשיו".** `src/lib/table.ts` מחיל על הטבלה את
משחקי היום: אם משחק הסתיים — התוצאה האמיתית; אם עוד לא התחיל — תחזית
("ניצחון היום ומכבי חיפה עוברת למקום 2"), מחושבת ממיון הטבלה מחדש, לא
מניחוש. הטבלה מתעדכנת עם הקאש כמה פעמים ביום — לא תוך כדי משחק.

**חדשות שנבנות מהנתונים, לא רק כותרות.** `src/lib/news.ts` מייצר
דיג'סט מתוך מה שכבר יש: תוצאה שהסתיימה (עם הסיכום משלוש השורות של
`src/lib/narrative.ts`), תנועת טבלה פסיבית (קבוצה שעלתה כי מישהו אחר
הפסיד), עדכון העברה. כותרות אמיתיות מ-RSS מתמזגות לאותו פיד כשהן
קיימות, עם שם המקור גלוי — הפיד תמיד עובד, גם בלי מקור חיצוני.

ליגות נתמכות: ליגת העל, הפרמייר ליג, ליגת האלופות, הליגה האירופית
וליגת הקונפרנס. ה-NBA קיים כהקשר ללגיונר בלבד (אבדיה) ולא כליגה
שגולשים בה — הדגל `legionnaireOnly` ב-`src/data/competitions.ts` שולט
בזה.

## איך הנתונים מגיעים

זו לא אפליקציית מעקב חי, ולכן אין שום קריאה חוזרת לספק מהדפדפן —
בשום מסך, אף פעם:

```
GitHub Action לפי לוח זמנים ──> api-football ──> סיכומים ב-Groq
                       │                              │
                       └──────────> RSS <─────────────┘
                                      │
                                      ▼
                        public/data/snapshot.json  ──>  הדפדפן
```

1. **api-football** (100 קריאות חינם ליום) — לוח משחקים, טבלאות,
   סטטיסטיקות שחקנים למי שבמעגל שלך.
2. **Groq / Llama 3.3 70B** — סיכום שלוש שורות למשחק שהסתיים. בלעדיו
   (או כשהקריאה נכשלת) — סיכום תבניתי מהנתונים, מסומן ככזה במפורש.
3. **RSS** — כותרות אמיתיות, מסוננות במילות מפתח כדי לא להציף בתוכן
   לא קשור. מקור אופציונלי; ברירת המחדל לא אומתה בזמן הכתיבה (ראה
   "הקמה" למטה).
4. **ספק דמו** כשאין קאש ואין מפתח, כדי שאפשר יהיה לפתח בלי חשבון.

בכל מסך יש שורת מקור שאומרת מתי הנתונים עודכנו לאחרונה. שום מספר לא
מתחזה למשהו שהוא לא.

### חוזה חשוב: הטבלה משקפת את המצב *לפני* היום

`src/lib/table.ts` מניח ש-`standings` בקאש הוא נקודת הפתיחה של היום —
בלעדיה, הטבלה הייתה סופרת את משחקי היום פעמיים (פעם מהטבלה הטרייה,
פעם מהחלת התוצאה בצד הלקוח). לכן `scripts/build-cache.mjs` מרענן טבלה
**לכל היותר פעם ביום לכל תחרות**, ולא בתגובה מיידית למשחק שהסתיים.
לוח המשחקים עצמו כן מתעדכן בכל הרצה — רק הבסיס שהתרחישים נמדדים ממנו
נשאר יציב לאורך היום.

### חיסכון בקריאות

- לוח משחקים נמשך בקריאה אחת לכל תאריך, בלי סינון ליגה — הסינון מקומי.
- טבלאות נמשכות פעם ביום לכל תחרות, לא יותר (ראה למעלה).
- אירועים וסטטיסטיקות שחקנים נמשכים רק למשחקים שמעניינים אותך, ורק
  פעם אחת לכל משחק — ההיסטוריה נצברת ב-`actions/cache` בין הרצות.
- סיכום נכתב פעם אחת לכל משחק ונשמר בקאש.
- RSS לא צורך שום קריאת api-football — מקור נפרד, זול, ונכשל בשקט.

## הקמה

### 1. מפתחות

| סוד/משתנה ב-GitHub | מאיפה | חובה? |
| --- | --- | --- |
| `API_FOOTBALL_KEY` (Secret) | [dashboard.api-football.com](https://dashboard.api-football.com) | כן |
| `GROQ_API_KEY` (Secret) | [console.groq.com/keys](https://console.groq.com/keys) | לא — בלעדיו הסיכומים תבניתיים |
| `NEWS_FEEDS` (Variable) | כתובות RSS מופרדות בפסיק | לא — בלעדיו רק דיג'סט מהנתונים |

Secrets תחת **Settings → Secrets and variables → Actions → Secrets**,
Variables תחת אותו מסך בטאב **Variables**.

**לגבי `NEWS_FEEDS`:** כתובת ברירת המחדל בקוד (`scripts/build-cache.mjs`)
לא אומתה בזמן הכתיבה — הסביבה שבה זה נכתב חסומה לרשת חיצונית. בדוק
שהיא עדיין עובדת (`npm run cache` מקומית ותסתכל על `[rss]` באזהרות),
ואם לא — מצא פיד RSS ישראלי לספורט ועדכן את `NEWS_FEEDS`.

### 2. מזהי ליגות

מזהי הליגות ב-`src/data/competitions.ts` ובראש `scripts/build-cache.mjs`
צריכים להיות זהים. אם ליגה חוזרת ריקה, שלוף את המזהים מהחשבון שלך:

```bash
API_FOOTBALL_KEY=xxx npm run leagues
```

### 3. Pages

הפעל GitHub Pages במצב **GitHub Actions** (Settings → Pages → Build
and deployment → Source). שני ה-workflows מפרסמים אליו: `deploy.yml`
בכל דחיפה ל-branch הראשי, ו-`refresh-data.yml` לפי לוח הזמנים.

## הרצה מקומית

```bash
npm install
npm run dev        # http://localhost:5173 — רץ על נתוני דמו
npm run build
npm run preview
npm run typecheck

API_FOOTBALL_KEY=xxx GROQ_API_KEY=yyy npm run cache   # בניית הקאש מקומית
npm run leagues                                        # שליפת מזהי ליגות
```

בלי מפתחות האפליקציה רצה על ספק הדמו: לוח משחקים, טבלאות, היסטוריית
לגיונרים ועדכוני העברות — כל המסכים עובדים.

## מה עוד אפשר להוסיף

- **זיהוי אוטומטי של לגיונרים** — הקאש כרגע לא סורק סגלי קבוצות לאיתור
  ישראלים; רשימת הלגיונרים היא הבסיס בקוד (`src/data/legionnaires.ts`)
  פלוס מה שתוסיף ידנית ממסך קבוצות.
- **פיד העברות אמיתי** — עדיין פיד עריכתי, מסומן ככזה.
- **דייג'סט בוקר כהתראה** — Action נפרד ששולח סיכום קבוע בשעה קבועה.
